# Contributing

Implementation repositories are private. Authorized developers start with `zenora-platform` for the service catalog, complete local stack and release instructions, then read the selected repository's README and AGENTS.md.

Use focused branches and pull requests. Include the behavior changed, relevant checks and any contract or migration implications. Preserve user data and existing client compatibility. Changes to shared packages require explicit version adoption by consumers.

Never include passwords, tokens, private prompts, uploaded photographs or production configuration in issues or pull requests. Public API documentation fixes can be proposed in `zenora-developers`.

GitHub Free is the current organization plan. Review conventions and ownership files do not imply that paid private-repository branch protections are enabled.
